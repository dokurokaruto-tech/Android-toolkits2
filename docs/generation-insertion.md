# 割り込み生成の検証

操作・API仕様: `pc-generation-agent/README.md` の「生成中の優先追加」。

## 自動検証

```sh
python -m pip install -r pc-generation-agent/requirements.txt
python -m unittest discover -s pc-generation-agent/tests -v
```

追加テスト:
- 100→101枚、実行中の1枚不変、優先順、シード・ステップ維持。
- 通常画像→サムネイル→再生成→通常画像の混在と保存先・結果対応。
- 同一IDの再送・並行送信で重複しない。違う内容の再送は拒否。
- 通常のpending更新が割り込みやサムネイルを変更しない。
- SQLite再起動後も優先度・再送IDを保持。
- 最終タスク終了との境界、停止後の拒否、不正入力の全件ロールバック。
- サムネイルの途中失敗で別のカード／プリセットにずれない。
- HTTP認証・202応答・再送。

PC側20テスト成功。変更Kotlinの構文検査も成功。

## 実機確認

1. 通常100枚の生成中、閲覧画像を同一シード・別ステップで割り込み。
   現在の画像→割り込み画像の順となり、総枚数101を確認。
2. 同じジョブへカード・プリセットのサムネイルを追加。
   通常閲覧にサムネイルが混ざらず、指定対象だけ更新されること。
3. サムネイル生成中に通常画像を割り込み、両方の後処理を確認。
4. ビルダーを編集しても割り込みの条件が変わらないこと。
5. 送信中の通信断・アプリ終了後の再接続で二重登録されないこと。
6. 「この1枚で終了」「今すぐ中断」の従来操作を確認。
