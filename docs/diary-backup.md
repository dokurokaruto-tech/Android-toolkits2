# 日記と写真のファイルバックアップ

Google Cloud Consoleへのアプリ登録やOAuth設定は不要です。Androidのファイル選択画面（SAF）でバックアップZIPを一度選び、アプリがそのファイルへの永続的な読み書き権限を取得します。

## 使い方

1. 「日記」画面上部の「バックアップ」を開きます。
2. 保存先を選びます。
   - **新しいバックアップを作成**: `DiaryBackup.zip` を新規作成します。
   - **既存のバックアップを選択**: このアプリの日記バックアップZIPを選びます。ローカルにない日記や写真は更新日時を確認して取り込みます。
3. ファイル選択画面でGoogle Driveが表示される場合は保存先として選べます。表示されない場合は、端末で利用できる別のドキュメントプロバイダーを選んでください。

バックアップに含めるのは日記本文と、その日記から参照されている写真だけです。保存先を設定すると、日記の保存後にZIPをバックグラウンドで更新します。「今すぐバックアップ」から手動更新もできます。失敗した更新は次回アプリ起動時に再試行します。

最後に正常保存した件数とデータ量を基準に、端末側の日記や写真が突然0件になった場合、または記録数／データ量が大幅に減った場合は自動上書きを停止します。復旧には「選択済みバックアップから復元」を使ってください。意図して大幅に削除した場合は、内容を確認してから手動バックアップの上書きを承認できます。

以前のバージョンが作成した、現在の日記アプリで扱わない旧データを含むZIPは、誤って消さないよう既存ファイルの更新を止めます。そのファイル自体は変更しません。日記だけのバックアップが必要なら、新しいZIPを作成してください。復元時も、日記と写真以外の項目は端末へ取り込みません。

## 注意

- 保存先プロバイダーが永続的な読み書き権限とファイル更新に対応している必要があります。
- 無関係なZIPは取り込みません。ローカルデータを削除することもありません。
- 以前の版にあった日記以外の記録ファイルは端末から自動削除せず残しますが、現在の画面・SAFバックアップ・Androidの自動バックアップでは扱いません。
- これは選択した1ファイルへのバックアップであり、複数端末間のリアルタイム同期ではありません。
- 「保存先の設定を解除」はURI登録とアクセス権だけを解除し、バックアップファイル自体は削除しません。
