# 編集コンシェルジュと返信通知

## 編集

- カード編集：メインプロンプト横の「相談」。新規カードも対応。
- タグ編集：メニューの「コンシェルジュ」。複数の文章があれば対象を選択。
- 文章編集：「この文章をコンシェルジュに相談」。新規文章も対応。

毎回、編集欄の最新の名前・本文・ネガティブを渡す。対象を検索し直さず、
開いた編集欄に固定する。文章LLMが変更案を作り、Jevが妥当性を検証する。
接続先・APIキー・モデルは既存コンシェルジュの設定を共有する。

比較画面で「編集欄へ反映」を選ぶまで変更しない。
待機中に編集内容が変わった場合や元の画面を閉じた場合は適用を拒否する。
相談を閉じると未完了の処理をキャンセルする。

反映後も未保存。元の編集画面で保存する。タグの文章は文章編集で保存した後、
タグ編集でも保存する。取消時に保存済みデータへ影響を残さないため、
この相談はグローバルな適用・取消履歴に登録しない。

## 返信通知

チャットオプション →「返信通知のON / OFF」。初期OFF。
Android 13以降ではON時に通知権限を要求する。OS側で拒否した場合はOFFに戻す。
OSでチャンネルを無効にしている場合は「Androidの通知設定」で許可する。

ローカル・クラウドの通常返信／再生成で、次のイベントを各1回通知する。

1. 最初の空白以外の本文を受信。
2. 正常完了。クラウドは終了マーカーまたは正常なfinish_reasonを確認。

「考え中」の表示、空応答、エラー、中断を完了通知にしない。
対象セッションを閲覧中のイベントは通知せず、後から再通知もしない。
開始を画面内で見てから離れた場合は完了のみ通知する。
通知を押すと画像の現在の結びつけではなく、通知元セッションを直接開く。
別の会話とのPendingIntentの混同を防ぎ、画面の再生成時にも対象を保持する。
生成中はアプリ側の生きた会話ツリーを使い、継続中の本文も表示する。

画像の結びつけが変わった／画像がなくなった場合は会話履歴だけを開き、
画像を古い会話へ結び直さない。削除済みの会話は開かず通知する。
対象の会話を開くと、その会話の返信通知を消す。OFFにすると返信通知を消す。
本文を通知に含めず、ロック画面ではPRIVATEとして扱う。

既存の推論用フォアグラウンドサービス通知は別枠。
OSが要求する常駐通知をこのON/OFFで消すものではない。
