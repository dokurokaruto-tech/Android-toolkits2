# 画像の読み込み方式

## フォルダ

- タップ後は一覧画面を先に開く。全画像の取得・生成条件の保存を画面遷移の条件にしない。
- PCは1.2.0以降が必要。SQLite索引とkeyset cursorで60件ずつ取得する。
  ファイル本体や生成情報を全件読み直してからページを切り出す方式ではない。
- 選んだフォルダの索引の初回作成・外部変更の走査は背景で行う。初回作成中も画面は先に開く。
  最初の索引作成時間・通信時間まで一定になる保証はない。
- 生成・削除で索引を更新。旧APIは互換用に残すが新版Androidでは使わない。
- スクロール／「続きを読み込む」で追加取得。全画面でも末尾付近で次ページを取得する。
  カウンター末尾の `+` は未取得ページがある印。「全選択」は読み込み済みの画像が対象。
- 端末のSAFフォルダはIOスレッドで列をまとめて問い合わせ、60件ずつ描画へ渡す。
  日付一覧では子フォルダ内を全件数えない。並び順の扱いはDocumentsProviderにも依存する。
- 生成条件はページ単位でまとめて保存。従来の画像ごとの全JSON書き直しを避ける。
- 全画面への移動では大量のURI配列をBinderに渡さず、アプリ内の一覧キーを渡す。
  プロセスが消えた場合はIntentに残した現在画像へ復帰する。

## 全画面

1. タップしたサムネイルの小さいコピーを引き継いで表示。
2. 原寸をアプリ所有の取得処理でキャッシュファイルへ保存。中央に回転インジケーターを表示。
3. ファイル全体の取得・デコードが完了したら一括で切り替える。

ページ送り時は保存済みサムネイルを先に読む。サムネイルが無ければ取得を待つ。
古いページのコールバックが現在の画像を上書きしないようリクエスト番号で判定する。
エラー時は回転表示を止め、サムネイルを残す。原寸を再試行するには画像を開き直す。
ストリップ配信・上からの段階描画は呼ばない。PCでのストリップ先行生成も廃止した。
原寸ファイルは変更しない。表示用Bitmapは画面サイズに合わせてデコードし、RAM消費を抑える。

## キャッシュ

- 原寸：`cache/original_images/`、LRU上限2GiB。1画像128MiBまで、同時取得2件。
- Glide：512MiBのディスクキャッシュ。リモート画像も対象。
- 既存の専用サムネイルキャッシュは従来の容量制限を維持。
- ページ移動・全画面を閉じる・RAM不足では、原寸ファイルも開始済み転送も消さない。
  RAMのBitmap・バイト列とディスク保存を別々に管理する。
- 転送中は`.part`。サイズ検証後にrenameし、完成前のファイルを読ませない。
  失敗時に部分ファイルを削除。プロセス終了で残った古い部分ファイルも整理する。
- 同じPC・同じ原寸URLへの同時要求は合流する。認証token変更でも再利用し、別PCとは分離する。
- 次回起動時もディスクを再利用。チャット背景や明示保存でも取得済み原寸を利用する。
- 上限超過時は古いキャッシュから整理する。OSのキャッシュ削除・ユーザーによる削除・
  空き容量不足は別であり、永久保存ではない。Androidがプロセスを終了すれば未完了転送は止まる。
- キャッシュにあるだけでは保存済みの緑枠にしない。保存済み判定は指定保存先の原画像を確認する。
- 日付一覧の画像メタデータ取得にはPC接続が必要。画像キャッシュはライブラリの完全なオフライン複製ではない。
